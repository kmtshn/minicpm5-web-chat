# MiniCPM Local AI Appliance

ブラウザ内で文章と画像を処理する、APIキー不要のローカルAIワークスペース。アプリ本体は引き続き **単一の `index.html`** です。ビルドやサーバーAPIは不要。PWA用に `sw.js`、`manifest.webmanifest`、`icon.svg` を追加しています。

## 主な機能

- ストリーミング表示と生成停止。停止・エラー時も途中の回答を保存。
- 実行方式、WebGPU API利用可否、Context、TTFT、生成tokens、tok/s表示。
- 端末性能に応じた2K / 4K / 8K Context切替。
- IndexedDBによる会話・圧縮画像の保存、履歴一覧、再起動時の復元。
- Markdown / JSONエクスポート。JSONは画像込みで再読み込み可能。
- TXT / MD / CSV / TSV / JSON / LOG / PDF / 画像の添付とドロップ。
- 要約、整文、翻訳、箇条書き、説明、ログ解析、返信文のクイックアクション。
- 画像添付時の「画像を説明」「文字を読む」「画像の要点」。
- 回答スタイル、temperature（0〜1.5）、最大生成tokens（32〜1024）設定。
- Light / Dark / Systemテーマ、スマートフォン対応。
- PWAホーム画面追加、オフライン資産準備、準備状況、通信遮断モード。

## 使い方

1. [アプリ](https://kmtshn.github.io/minicpm5-web-chat/)を開きます。新画面はこの改修のマージ・Pages反映後に公開されます。
2. 文章を入力、またはファイルを添付。クイックアクションは指示を入力欄に追加します（自動送信しません）。
3. 「モデルを準備」または「送信」を押します。初回・モデル切替・Context変更時には大容量ロードを確認します。
4. 「生成停止」で中断。実行中の処理が戻った時点で反映されるため、前処理中は待ち時間があります。
5. 重要な会話はJSONでバックアップしてください。

モデルは自動ダウンロードしません。ロードに失敗した場合はContextを2Kにして再試行できます。

## モデル・ランタイム

| 選択 | 動作 |
| --- | --- |
| AUTO | 今回画像を添付した場合はMiniCPM-V 4.6、それ以外はMiniCPM5-2B |
| MiniCPM5-2B | テキスト専用。画像添付時は送信前に案内 |
| MiniCPM-V 4.6 | 画像＋テキスト。ロード後に画像対応を検査 |

既存のモデル定義を維持しています。

- [openbmb/MiniCPM5-2B-GGUF](https://huggingface.co/openbmb/MiniCPM5-2B-GGUF): `MiniCPM5-2B-Q4_K_M.gguf`（既存目安約1.56GB）。
- [ggml-org/MiniCPM-V-4.6-GGUF](https://huggingface.co/ggml-org/MiniCPM-V-4.6-GGUF): Q4_K_M + Q8_0 projector（既存目安約1.26GB、配布元の構成に依存）。
- [wllama 3.6.1](https://www.npmjs.com/package/@wllama/wllama/v/3.6.1): バージョン固定、jsDelivrから取得。
- [PDF.js 4.10.38](https://www.npmjs.com/package/pdfjs-dist/v/4.10.38): PDF利用時に遅延取得。

GitHub Pagesでは任意の分離ヘッダーを設定できないため `n_threads: 1` を維持しています。WASMとランタイムのGPU自動選択を利用します。**WebGPU APIが存在するだけでGPU推論中とは表示しません**。GPU実稼働は公開APIで確定できず、未確認と明示します。ブラウザによって互換WASM資産が必要です。

## Context・性能計測

- モバイル、メモリ情報不明、メモリ情報4GB以下は2Kまで。
- その他は4K、メモリ情報8GB以上のPCは8Kまで（初期値4K）。ブラウザの情報は概算であり、動作保証ではありません。
- 入力をUTF-8バイト数で保守的に見積もり、出力枠・テンプレート余裕・画像余裕を確保します。厳密なトークナイズではありません。
- 最新入力が収まらない場合は送信を拒否し、短縮・分割を案内します。ファイルを黙って切り捨てません。
- 過去の完了済み会話を、新しい順にユーザー／回答のペアで選びます。送信から外しても保存履歴は消えません。
- 画像tokensはランタイムに依存し、予約枠を超える場合は生成エラーになります。2Kで全画像を処理できる保証はありません。
- TTFTは生成API呼び出しから最初の本文まで。モデル取得時間は含みません。
- tokensはランタイムの `usage.completion_tokens` を使用。tok/sはAPI呼び出しからの経過時間で割った**前処理込みの平均速度**。
- usage未提供や停止時は「未提供」と表示します。文字数・チャンク数でtoken数を偽装しません。

## 添付・履歴互換

画像は従来どおり長辺1600px以下、JPEG品質0.88へ縮小します。画像1枚、添付合計6個まで。1ファイル20MB以下。テキストは1MB・10万文字以下、PDFは50ページ・抽出10万文字以下。送信可能な長さはContextによってさらに制限されます。

テキストはUTF-8として読み、不正な文字コードは拒否します。PDFはテキスト層の抽出のみです。OCR、暗号化PDFのパスワード入力、表レイアウトの再現は非対応。スキャンPDFは画像を添付するか、必要な文章をコピーしてください。

過去の画像は画面と保存履歴に残しますが、次の推論には説明テキストだけを渡します。再解析時は画像を再添付してください。

JSON復元は本アプリの `version: 1` 形式、従来の `{role, content}` 配列、`{messages: [...]}` に対応。旧マルチモーダル配列のテキストは保持し、JSONで復元できないArrayBuffer画像は再添付を案内します。旧版は会話を永続保存していなかったため、終了済みセッションの自動復元はできません。旧 `minicpm-model` 設定は引き継ぎます。

IndexedDBが使えない場合はタブ内のみで動作し、警告します。容量不足も表示します。生成中は約2秒間隔、終了時は直ちに保存。強制終了では直前の出力が失われる場合があります。複数タブで同じ会話を編集した場合は最後の保存が優先されます。

会話・ファイル名・モデル出力は `textContent` で表示し、HTMLとして実行しません。Markdown書き出しは対応しますが、回答画面はプレーンテキスト表示です。

## PWA・オフライン・通信

1. オンラインで開き、設定の「オフライン資産を準備」を押します。
2. 必要なモデルをロードします。GGUFはwllamaのキャッシュに保存し、Service Workerに重複保存しません。
3. アプリ・実行資産・PDF・モデルの準備状況を確認します。モデルはwllamaでファイルサイズと構成を検証します。
4. 対応ブラウザの「ホーム画面に追加」を使用。ボタンがない場合はブラウザのメニュー／共有メニューから追加してください。
5. 機内モードで再度開き、モデルをキャッシュからロードできるか確認してください。

初回制御に再読み込みが必要な場合があります。有効なモデルキャッシュがあれば、Hugging Faceへ照会せず直接ロードします。保存領域は容量制限や自動削除の対象であり、準備状況だけで再起動後の完全オフライン動作は保証しません。

「通信遮断モード」はロード後に有効化でき、Service Workerの制御対象HTTP(S)リクエストをキャッシュ限定にします。未保存リクエストは503で拒否。状態は保存し、Worker再起動後も維持します。モデル／Context変更は解除後に行ってください。ページ再読み込み後はキャッシュ済みモデルを準備できます。

これは**このアプリの通信制限**です。制御前・既に進行中のリクエスト、ブラウザ自身・拡張機能・制御対象外Workerなど、端末全体の通信は遮断しません。厳密な通信遮断にはOSの機内モード等を併用してください。会話やファイルを外部AI APIへ送信する実装はありません。

オンライン時の取得先はGitHub Pages、jsDelivr、Hugging Faceとその配信先。PDF取得もあり、「モデルロード済み＝今後すべての外部通信なし」とは表示しません。

## 開発・公開・検証

本体のHTML内にアプリロジックとCSSを配置し、追加ファイルはPWA資産と依存なしの `tests.cjs` のみ。静的HTTPサーバーまたはHTTPSで公開してください。`file://` ではモジュールとService Workerは動作しません。

GitHub Pages: Settings → Pages → Deploy from a branch → `main` / root。PRをマージしてから反映されます。アプリ更新はオンライン時に取得します。依存バージョン変更時はService Workerの資産リストも更新してください。

```sh
node --test tests.cjs
```

テストは履歴互換・入力長・画像履歴・ストリーム描画・停止後の再生成・エラー時の保存・通信遮断の再起動維持・資産準備を、実モデルのダウンロードなしで検証します。

対象端末では別途、実モデルのテキスト／画像生成、停止、切替、PWAインストール、機内モードでの再起動を確認してください。大容量ロードや生成品質は自動テスト対象外です。

モデル、wllama、PDF.jsのライセンスは各配布元の条件に従ってください。
